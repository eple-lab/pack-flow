# 00. 개요

작성일: 2026-11-20 · 근거: [계획서 1~3절](pack-flow-plan.md), 해커톤 ERP 주제 안내

## 1. 한 문장

> 소규모 판매자(구매대행 · 부업 포함)가 엑셀과 메모로 따로 관리하던 **구매 → 입고 → 재고 → 출고** 흐름을 한 화면에서 다루고, **거래가 일어나면 재고가 저절로 맞는** 미니 ERP.

## 2. 사용자와 문제

계획서 2절에는 팀원 세 명의 문제 문장이 따로 있다. 피드백 기준 1번("팀원 모두 같게 설명")을 위해 아래 하나로 합쳤다(P-01 · D-16, 계획서 2절 반영). 세 문장은 사라지지 않고 각자 아래 칸에 들어간다.

| 칸 | 내용 | 원래 문장 |
|---|---|---|
| 사용자 | 혼자 또는 소수로 구매대행 · 부업 판매를 하는 판매자 1인 (계정 하나 = 사업자 하나) | 공통 |
| 지금의 문제 | 구매 → 입고 → 판매를 엑셀과 메모로 따로 관리해서 재고가 안 맞고, 품절을 늦게 알고, 잘못 입력한 입출고를 고친 흔적이 남지 않는다 | skygaul · jkspawn |
| 바라는 상태 | 입고 확정 · 출고 처리만 하면 재고와 이력이 자동으로 맞고, 부족하면 먼저 알려 주고 발주 초안까지 만들어 준다 | eple(업무 자동화) |
| 정정 흐름 | 부족 발견 → 발주 → 입고 → 출고 차단 → 정정(취소 기록) | jkspawn |

## 3. 대표 시나리오 (입력 → 행동 → 결과)

판매 주문을 CSV로 붙여 넣는다 → 출고 처리하면 재고가 자동 차감되고 이력이 남는다 → 안전재고 아래로 떨어진 품목에 '품절 임박' 카드가 뜨고, AI가 만든 발주서 초안을 확인 후 등록하면 구매 내역에 '발주완료'로 반영된다.

시연 순서(ERP 주제 안내): 로그인 → 입고 → 출고 → 품절 임박 카드 → 발주서 초안 확인 → 취소 · 거부 사례 → B 계정 권한 거부. `demo` 시드에서는 출고를 입고보다 먼저 해야 품절 임박 카드가 뜨므로 실제 순서는 [화면 구성 9절](wireframes.html) (`id="demo"`)을 따른다.

## 4. 범위

| 구분 | 내용 |
|---|---|
| MVP (Step 1~5, 모두 필수) | 입고 · 출고 → 재고 → 대시보드 / 인증 + RLS + Render 배포 / 취소 · 상태 전이 · 마이너스 재고 방지 · 일괄 등록 / 상호 리뷰 · 대량 데이터 · 회귀 테스트 / AI 발주 초안 · 자연어 조회 · 출고 |
| MVP 이후 | 계획서 4절 '고도화 후보'. 발표 자료 완료 후 희망자가 고른다 |
| 하지 않음 | 회계 · 세무, 다중 창고, 실시간 택배 API, 실제 결제, 창고 모니터링(YOLO), 역할별 세밀한 권한 |

## 5. 성공 기준

- **팀 달성 판정**: 달성 = Step 1~5 완료 / 부분 달성 = 하나라도 미완료 / 미달성 = Step 1 미완료 (계획서 14절)
- **완료 판정 테스트**: 계획서 2절의 1~6번 + Step별 통과 테스트. 각 테스트를 누가 어떤 파일로 자동화하는지는 [07 테스트 전략](07-test-strategy.md)에 있다.
- **피드백 기준 5개**(명확성, 실제 동작, 테스트 · 권한, AI 검토, 협업 · 전달)마다 증거 위치를 [07](07-test-strategy.md) 5절에 미리 정해 둔다.
