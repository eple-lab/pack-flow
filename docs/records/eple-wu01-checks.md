## 2. 시험에서 찾아 고친 결함

| # | 문제 | 어떻게 알았나 | 원인 | 고친 것 | 다시 확인 |
|---|---|---|---|---|---|
| D-1 | 검사 스크립트를 커밋하면 스크립트 자신이 걸림 | H-14: 시험 저장소의 첫 커밋이 막힘 | 맥 · 리눅스 경로 패턴의 글자가 경로 모양 그대로라 자기 자신과 맞음 | 패턴의 `/`를 `[/]`로 써서 글자 자체는 경로 모양이 아니게 | 첫 커밋 통과, H-06 여전히 막힘 |
| D-2 | 걸린 키 값이 그대로 출력됨 | H-13: 출력에 가짜 키 전체가 보임 | 걸린 줄을 그대로 찍음. 공개 저장소의 Actions 로그는 누구나 본다 | 출력할 때 걸린 부분을 `‹가림›`으로 바꿈 | H-13, A-02 로그 확인 |
| D-3 | 출력을 끊으면 훅이 막지 못함 | H-12: `\| head`를 붙인 커밋이 들어감 | 출력 파이프가 닫히면 훅이 신호로 죽고 커밋이 진행됨 | 훅이 검사 결과를 먼저 변수에 받고 종료 코드를 따로 지킴, 파이프 신호 무시 | H-12 막힘, 깨끗한 커밋은 통과 |
| D-4 | git diff가 실패해도 "깨끗함"으로 끝남 | R-02: 잘못된 범위인데 종료 코드 0 | diff 오류를 확인하지 않고 빈 결과로 봄 | diff 실패 시 종료 코드 2로 멈춤 | R-02 |

네 건 모두 이 세션의 AI(Claude)가 처음 쓴 코드에서 나왔고, 기대 결과를 먼저 적고 돌린 시험에서 잡혔다. 제출용 AI 사례 후보다.
