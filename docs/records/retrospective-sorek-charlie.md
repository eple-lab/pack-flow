# 회고 — sorek-charlie

- 맡은 영역 — 입고·출고 및 취소 재고 함수(WU-21·23), 시드와 E2E(WU-22), 회귀 검증(WU-24)
- 작성 — 2026-11-25. 에이전트가 프로젝트 기록을 바탕으로 정리했고, 본인이 전체 내용을 확인했다.

## 1. 시작할 때 기대한 것

프로젝트를 시작할 때는 입고, 출고, 취소가 실제 재고에 반영되는 흐름을 처음부터 끝까지 만들어 보고 싶었다. 특히 출고를 취소했을 때 재고가 원래 수량으로 돌아오고, 어떤 거래가 취소됐는지 이력에서도 확인할 수 있게 하고 싶었다. 팀원들이 만든 화면과 API를 재고 로직에 연결한 뒤, 실제 배포 환경에서 전체 흐름을 테스트해 보는 것도 기대했다.

## 2. 처음 생각과 달라진 점

| 처음 생각 | 실제로 겪은 일 |
|---|---|
| 재고가 예상한 수량과 맞으면 검증이 끝난다. | 재고가 다시 열 개라는 결과만으로는 거래가 없었는지, 여섯 개를 출고했다가 취소했는지 구분하기 어렵다. 재고 수량과 거래 이력을 함께 확인했다. |
| 출고를 거부했는지는 오류 표시로 확인할 수 있다. | 재고 부족으로 출고를 거부할 때 수량과 이력도 그대로 남는지 검증했다. |

## 3. 느낀 점

출고와 취소가 어떤 순서로 일어났는지 이력에서 확인할 수 있어야 재고 수량을 설명할 수 있었다. 출고와 취소를 한 시나리오로 검증하니 이 원칙이 실제 화면에서 어떻게 보이는지도 확인할 수 있었다.

## 4. 에이전트를 다루면서 성장한 점

- 발표 대본이 초안의 배정대로 작성됐을 때 최종 사용 버전과 담당 슬라이드 범위를 지정해 수정했다.
- PR 검토 결과를 근거와 함께 정리하게 하고, 승인 여부를 GitHub 리뷰에서 확인했다.

## 5. 어려웠던 일

- 출고 취소 뒤 재고가 복구되는지와 원래 이력이 남는지를 한 시나리오에서 검증하는 일이 필요했다.
- 로컬 단위 시험과 배포 브라우저 시험의 결과를 구분해 해석해야 했다. 첫 회귀에서는 시드 JSON 로딩이 Playwright에서 실패했다([PR #69](https://github.com/eple-lab/pack-flow/pull/69)).

## 6. 힘들었지만 잘했다고 생각하는 일

- 재고 함수와 취소 흐름을 구현하고, 시드 세 벌의 예상값으로 실제 결과를 검산했다([PR #29](https://github.com/eple-lab/pack-flow/pull/29), [PR #40](https://github.com/eple-lab/pack-flow/pull/40), [PR #44](https://github.com/eple-lab/pack-flow/pull/44)).
- 최종 dev 회귀에서 출고 취소, 초과 출고 거부, 계정 격리를 포함해 66건 통과를 확인했다([11/25 회귀 결과](regression-20261125-1056.md)).

## 7. 아쉬웠던 일

- 같은 품목에 출고 요청 두 건이 동시에 들어오는 상황은 이번 검증에서 다루지 못했다.
- 최종 회귀 기록은 dev 기준이다. 시연 환경에서 같은 항목을 직접 확인한 결과도 남겼으면 검증 범위가 더 분명했을 것이다.

## 8. 배운 점

- 성장 면 — 기대 결과를 성공 여부, 재고 수량, 이력 변화로 나눠 적으면 검증 결과를 설명하기 쉽다. 실패 사례도 전후 상태를 비교해야 한다.
- 학습 면 — 동일한 시드와 예상값으로 여러 환경을 검증할 수 있다. 단위 시험과 배포 브라우저 시험은 서로 다른 실패를 드러낸다.

## 9. 더 공부하고 싶은 것

- 재고 네 개에 세 개씩 출고하는 요청 두 건을 동시에 보내 한 건만 승인되는지, 최종 재고와 이력이 일치하는지 확인하는 동시성 테스트.
- 배포 환경에서 발생한 실패를 회귀 결과표에 재현 가능한 근거로 남기는 방법.
