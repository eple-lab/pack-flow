# AI 한계 문서 — 못 하는 것 · 막아 둔 것 · 데이터 정책

갱신: skygaul · 2026-11-24 · 배포 Gemini 리허설 결과(503 · 지연 · T-AI) 반영
작성: skygaul · 2026-11-23 · WU-35 · 근거: [05 보안](../05-security.md) 4절, [02 결정](../02-decisions.md) D-06 · P-08 · P-09 · P-14, [04 API 계약](../04-api-contract.md) 3.8, 계획서 15절

> 한 줄로: **AI는 초안을 쓰고 요청을 해석할 뿐이고, 숫자는 코드가 정하고, 실행은 사람이 [확인] · [실행]을 눌러야 한다.** 아래는 그 원칙에서 AI가 할 수 없는 일, 그래서 막아 둔 장치, 외부 모델에 보내는 데이터의 범위다.

## 1. AI가 하지 못하는 것

| 한계 | 왜 그런가 | 사용자에게 보이는 모습 | 근거 |
|---|---|---|---|
| 추천 수량은 단순 공식이다 | `max(0, ceil(최근 7일 일평균 출고 × 리드타임 7일) + 안전재고 − 재고 − 입고 예정)`. 계절 · 행사 · 거래처 사정은 모르고, 7일 창의 `실판매출고`만 센다 | 발주서 초안 표의 "근거" 칸에 계산 근거가 그대로 적힌다. 출고 이력이 없으면 안전재고까지 채우는 양(안전재고 − 재고 − 입고 예정)만 추천한다 | `src/lib/agent/reorder.ts`, WU-32 |
| 발주서는 실제로 발송되지 않는다 | 이 앱의 [발주 등록]은 구매(`발주완료`)를 저장할 뿐이고 메일 · 메신저 연동이 없다. AI가 쓴 문안은 참고용이다 | 패널에 "발주서 발송(시연용)" 안내가 항상 보인다 | 계획서 15절, WU-33 |
| 문안 속 숫자를 믿을 수 없다 | LLM이 표와 다른 숫자를 쓸 수 있다. 저장은 사용자가 확인한 표 값만 쓰고 문안은 저장에 들어가지 않는다 | 문안 상자 위에 "참고용" 표시, 표가 기준 | WU-33 D-6 |
| 한 번에 한 가지만 해석한다 | 챗봇은 메시지 하나를 액션 하나로 바꾼다. 이전 대화를 기억하지 않는다("그거 4개 출고해 줘"는 못 알아듣는다) | 품목을 못 찾으면 "어떤 품목인지 알려 주세요" | `actions.ts` `handleChat`, 프롬프트에 이번 메시지만 들어감 |
| 비슷한 이름은 헷갈린다 | 이름이 여럿에 걸치면(예: "케이블") 서버가 고르지 않고 후보를 보여 주며 되묻는다. 오타 · 줄임말은 못 찾는다 | "품목이 여러 개예요: …. 어떤 품목인지 알려 주세요" | `findItem`, 시험 K-3 · H-3 |
| 허용 액션 6개 밖은 못 한다 | 삭제 · 재고 직접 수정 · 시드 초기화 · 일괄 처리는 만들지 않았다 | "그 요청은 도와드릴 수 없어요…" | 04 3.8, 시험 V-2 · H-8 · T-AI-4 |
| 작은 모델은 지시를 덜 따른다 | 개발용 Ollama(`qwen3.5:0.8b`)는 허용 밖 요청에 `unsupported`를 내라는 지시를 따르지 않고, 인젝션 문장에서 없는 구매 번호를 지어냈다. 그래서 프롬프트가 아니라 서버 검사가 막는다 | 거부 문장이 나오고 제안 카드는 안 뜬다 | AI 사례 3 |
| 많은 품목에는 약하다 | 챗봇은 품목을 200개까지만 읽고 프롬프트에는 100개까지만 넣는다 | 이 범위를 넘으면 뒤쪽 품목은 이름으로 못 찾는다 | `actions.ts` `ITEM_LIMIT`, `prompts/chat.ts` `MAX_ITEMS` |
| 발주 확정은 줄 사이 트랜잭션이 없다 | 줄마다 DB 함수를 한 번씩 부른다. 중간 줄이 거부되면 앞 줄은 저장돼 있다 | 저장된 줄은 표에서 빠지고 안내가 뜬다(다시 눌러도 중복 발주 안 됨) | WU-33 후속 PR, 04 3.8 |
| 응답이 느리거나 실패할 수 있다 | 외부 서비스라 20초 제한(`LLM_TIMEOUT_MS`)이 있고 503 · 429가 난다. 실제 Gemini가 개발 PC에서 2번, **배포(11/24)에서 챗봇 1번 503**을 돌려줬다(Gemini 서버가 처리 못 한다고 답함, 무료 등급 모델의 일시 과부하로 보임). 같은 설정으로 직전 초안 3건은 성공했고 다시 시도한 챗봇 5건도 성공했다. 지연은 초안 1.4 ~ 12.6초로 편차가 크다. 재시도 로직은 아직 없어 사용자가 다시 눌러야 한다(#59) | 초안은 표만 남고 문안 자리에 이유가 보인다(P-08). 챗봇은 "AI가 지금 응답하지 않아요" 오류 배너가 뜬다. 입출고 화면은 그대로 쓸 수 있다 | `llm.ts`, WU-33 V-2, [llm-usage.md](llm-usage.md) 4절 |
| 하루 호출 수가 정해져 있다 | 사용자당 30회, 앱 전체 300회(P-09). 개발 모드에서는 패널을 열 때 초안 요청이 두 번 나가 상한이 더 빨리 찬다 | "오늘 AI 사용 한도를 다 썼어요…" | 02 P-09, `llm.test.ts` T-AI-7 |
| 모델마다 답이 다르다 | 같은 문장도 Ollama와 Gemini가 다르게 해석할 수 있다. 서버 검사 로직은 모델과 무관하게 같지만 문안 품질 · 해석 정확도는 모델에 따른다. 배포 Gemini(11/24)에서 T-AI-1 · 2 · 4가 같은 결과(저장 · 거부 · 거절)였고 챗봇 5문장이 모두 서버 값으로 답했다. Ollama와의 문장별 비교표는 따로 남긴다 | 문안은 호출마다 조금씩 달랐다(같은 후보로 3번 만들어도 표현이 다름). 숫자는 항상 표 값이다 | 계획서 8절, [llm-usage.md](llm-usage.md) 4절 |

## 2. 막아 둔 것

| 위험 | 막아 둔 장치 | 어디서 | 시험 |
|---|---|---|---|
| LLM이 허용 밖 액션을 낸다 | 허용 액션 6개를 스키마로 검사하고 밖이면 거부한다 | `validateAction`, 라우트 스키마 | V-1 · V-2 · H-8, 실제 DB T-AI-4 |
| LLM 응답으로 DB가 바로 바뀐다 | 쓰기는 `/execute` · `/confirm`에서만, 사람이 [실행] · [발주 등록(확인)]을 누른 뒤. 받은 액션을 처음부터 다시 검사한다 | `executeAction`, `confirmPoLines` | C-01 · C-02, X-1 · X-9, T-AI-1 |
| LLM이 숫자를 지어낸다 | 답 문장과 수치는 코드가 DB 값으로 만들고 `facts`에 출처를 적는다. LLM 글은 어디에도 그대로 나가지 않는다 | `handleChat` | H-1(가짜 LLM이 999를 말해도 답에 없음), T-AI-3 |
| LLM이 품목 · 번호를 지어낸다 | 품목은 내 품목 목록에서 서버가 다시 찾는다. 주문 · 구매 번호는 사용자 메시지에 실제로 있을 때만 제안한다 | `findItem`, `mentions` | K-1~3, H-12b, AI 사례 3 |
| 재고보다 많이 출고한다 | 제안 전(chat) · 판매를 만들기 전(execute) · DB 함수, 세 번 막는다. 출고 직전에 달라져 거부되면 만든 판매를 `주문취소`로 닫는다 | `handleChat`, `executeAction`, `pf_ship_sale` | H-7, X-2 · X-3, T-AI-2 |
| 다른 사용자 데이터가 보인다 | 항상 사용자 JWT 클라이언트만 쓰고(RLS) 서비스 키를 쓰는 코드가 `src/`에 없다. 프롬프트에 다른 계정 데이터가 들어갈 경로가 없다 | `src/lib/supabase/server.ts` | H-13, X-7, 실제 DB T-AI-5 |
| 사용자 입력이 시스템 지시가 된다 | 사용자 메시지 · 품목 이름은 프롬프트의 '자료' 구역에 넣고(꺾쇠 · 줄바꿈 제거) 시스템 지시에는 섞지 않는다 | `prompts/chat.ts` · `draft-po.ts` | P-1 · H-14 |
| LLM 글이 화면에서 실행된다 | 모든 LLM 응답은 글자로만 렌더링한다(`dangerouslySetInnerHTML` 금지, lint `react/no-danger`) | `ChatView`, `DraftPoView` | Q-6, V-6 |
| 남용 · 한도 소진 | 호출 전에 `pf_llm_take`로 사용자당 30 · 전체 300 상한을 확인한다 | `src/lib/llm.ts` | T-AI-7 |
| LLM이 죽었을 때 가짜 결과를 보여 준다 | 미리 써 둔 문안을 AI 결과처럼 보이지 않는다. 표는 코드가 계산한 값 그대로 | `createPoDraft` | D-3 · V-2, T-AI-6 |

## 3. 외부 모델로 보내는 데이터와 무료 티어 정책

### 보내는 것
- **발주서 초안**: 계산된 후보 표(품목코드 · 이름 · 재고 · 안전재고 · 추천 수량 · 단가 · 거래처 이름 · 근거 문장)와 오늘 날짜
- **챗봇**: 사용자가 입력한 메시지(500자까지)와 내 품목의 코드 · 이름(재고 · 단가 수치는 넣지 않는다)
- **보내지 않는 것**: 이메일 · 비밀번호 · 키 · 사용자 ID · 로그인 정보. 프롬프트 전문은 로그에도 남기지 않는다(`log.ts`는 길이만 남김)

### Gemini 무료(unpaid) 티어의 데이터 정책 — 2026-11-23 확인
- Gemini API 추가 약관에 따르면 **유료 요금 없이 쓰는 서비스(무료 할당량 포함)에서는 Google이 입력과 출력을 제품 · 머신러닝 기술 개선에 사용할 수 있고, 사람 검토자가 (식별자를 제거한 상태로) 읽을 수 있다.** 약관은 민감하거나 개인적인 정보를 넣지 말라고 안내한다.
- **유료 서비스**(결제 계정이 연결된 프로젝트)에서는 Google이 프롬프트와 응답을 제품 개선에 쓰지 않는다. 기준은 할당량 종류가 아니라 **프로젝트에 활성 결제 계정이 연결됐는지**다.
- 유럽 경제 지역(EEA) · 스위스 · 영국에서는 무료 할당량에도 유료 서비스의 데이터 약관이 적용된다.
- 약관은 바뀔 수 있다. 출처: [Gemini API Additional Terms of Service](https://ai.google.dev/gemini-api/terms), [Gemini Developer API pricing](https://ai.google.dev/gemini-api/docs/pricing)(모델별 "Used to improve our products" 열).
- 그래서 이 프로젝트는 **시드 · 시험 · 시연 데이터는 모두 가상 데이터**이고(05 4절 '데이터 학습' 줄), 리허설 · 발표에서 실제 거래처 · 개인 정보를 입력하지 않는다. 발주서 문안에 들어가는 거래처 이름도 가상이다.
- 개발 중 쓰는 Ollama는 각자 PC에서 돌아가므로 입력이 외부로 나가지 않는다(D-06).

## 4. 사람이 해야 하는 것

- 발주 수량 · 거래처 · 금액을 표에서 **확인하고 고친 뒤** [발주 등록(확인)]을 누른다. 서버는 범위만 확인한다.
- 챗봇이 제안한 출고 · 상태 변경은 카드의 내용을 읽고 [실행]을 누른다. [취소]는 아무것도 바꾸지 않는다.
- 실제 발송(메일 · 메신저)은 사람이 따로 한다.
- 문안에 쓰인 숫자가 표와 다르면 표를 믿는다.
