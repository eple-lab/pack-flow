# 회고 양식 — 자기 작업 영역 (인터뷰로 작성)

> 제출물 '팀원별 기여 · 회고'의 근거. **발표 문서까지 쓴 뒤**(11/25) 각자 작성한다.
> 결과 파일: `docs/records/retrospective-<GitHub아이디>.md` (사람마다 한 파일 — 한 파일을 여럿이 고치면 충돌)

## 작성 방법 — 에이전트가 사람을 인터뷰한다

자기 AI 코딩 도구(에이전트)에게 이 파일을 주고 아래처럼 시킨다.

> `docs/records/templates/retrospective.md`를 읽고, 나를 인터뷰해서 내 회고 `docs/records/retrospective-<내 아이디>.md`를 써 줘.

에이전트가 지킬 것:

1. **질문은 한 번에 하나씩**, 아래 '인터뷰 질문' 순서대로 묻는다. 답이 짧으면 "예를 하나 들어 주실래요?"처럼 한 번만 더 묻는다.
2. 답을 지어내지 않는다. 사람이 말하지 않은 내용은 빈칸으로 두고 "(답 없음)"이라고 쓴다. 숫자 · PR 번호는 사람이 말했거나 저장소에서 확인한 것만 쓴다.
3. 근거를 붙일 수 있으면 붙인다 — 자기 PR(`#번호 WU-xx`), [13 고친 기록](../../13-fixes.md), `ai-cases-<아이디>.md`의 사례 번호, [일자별 기록](../../daily/).
4. 사람 말투를 살려 정리하되 문장은 짧게. 개수 기준(2~3개)을 넘으면 사람에게 고르게 한다.
5. 다 쓰면 **초안을 보여 주고 확인받은 뒤** 저장한다. 커밋 · PR은 사람이 정한다.
6. 공개 저장소다 — 실명 · 이메일 · 비밀번호 · 키 · PC 경로를 쓰지 않는다. 팀원은 GitHub 아이디로만. 남을 탓하는 문장은 "무엇이 어려웠나"로 바꿔 쓴다. 사람이 붙여 넣은 원문(노션 · 메신저 등)에 실명이 있으면 옮기지 않는다.
7. **질문마다 후보를 먼저 보여 준다** — 저장소 기록(PR · 이슈 · 일자별 기록 · AI 사례)에서 근거가 있는 후보 3~4개를 질문과 함께 보여 주고, 사람이 고르거나 새로 말하게 한다. "해당 없으면 넘겨도 된다"고 덧붙인다.
8. **앞 답에서 뒤 질문 후보를 모은다** — 한 답에 다른 질문의 내용이 섞이면(예: 3번 느낀 점에 5 · 6번 내용) 그 질문의 후보로 빼 두었다가 해당 질문에서 먼저 보여 준다. 같은 일을 다른 각도로 묻는 질문(3 느낀 점 ↔ 6 잘한 일)은 "그 일을 잘한 일로 보면?"처럼 이어서 묻는다.
9. **이전부터 해 온 습관은 따로 모은다** — 4번은 '이 프로젝트 기간 안'의 성장만 쓴다. 그 전부터 해 온 습관은 빼서 [AI 활용 현황](ai-usage.md) 파일의 '이미 잘하는 것' 근거로 넘긴다.

| 1 | 프로젝트 시작할 때(1일차 11/19) 기대한 것 — "이 프로젝트에서 이런 것까지 해 볼 거야" | 자유 |
| 2 | 처음 생각과 달라진 점 — 생각만 했던 것 vs 실제로 해 보며 겪은 일 | 2~3 |
| 3 | 느낀 점 | 2~3줄 |
| 4 | 에이전트(AI 코딩 도구)를 다루면서 성장한 점 — 이 프로젝트 기간 안에서 | 2~3 |

| 6 | 힘들었지만 잘했다고 생각하는 일 | 2~3 |

| 8 | 배운 점 — 성장 면 / 학습 면 | 각 2~3 |
| 9 | 더 공부하고 싶은 것 | 2~3 |
