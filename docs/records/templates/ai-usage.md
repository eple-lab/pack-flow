# AI 활용 현황 양식 — 에이전트가 본 나

> 프로젝트 동안 함께 일한 에이전트(AI 코딩 도구)가 **사람의 AI 활용 방식**을 관찰해 쓴다. 회고([retrospective.md](retrospective.md))와 짝이다. 11/25 작성.
> 결과 파일: `docs/records/ai-usage-<GitHub아이디>.md` (사람마다 한 파일)

## 작성 방법 — 에이전트에게 시킨다

> `docs/records/templates/ai-usage.md`를 읽고, 이 프로젝트에서 내가 AI를 쓰는 방식을 보고 `docs/records/ai-usage-<내 아이디>.md`를 써 줘.

에이전트가 지킬 것:

1. **근거는 실제 기록에서만** — 이 프로젝트의 대화, 내 PR · 리뷰 댓글 · 이슈, `ai-cases-<아이디>.md`, 일자별 기록. 대화를 볼 수 없으면 저장소 기록만 쓰고 그렇다고 밝힌다.
2. 근거 칸에는 사람이 한 말이나 행동을 **짧게 인용**한다(한 줄, 따옴표). 지어내지 않고, 짐작은 "(추측)"이라고 쓴다.
3. 칭찬만 쓰지 않는다. '다음 단계'는 실제로 헷갈림 · 되묻기 · 다시 하기가 생긴 장면에서 뽑는다.
4. 수준은 아래 기준 하나를 고르고 이유를 한 줄 쓴다. 네 명이 같은 기준을 쓰게 하려는 것이지 점수 매기기가 아니다.
5. 초안을 보여 주고 본인이 확인 · 수정한 뒤 저장한다. 공개 저장소다 — 실명 · 이메일 · 키 · PC 경로 금지, 팀원은 GitHub 아이디로만.

**수준 기준 (하나 고름)**

| 수준 | 모습 |
|---|---|
| 입문 | 한 번 묻고 받은 답을 그대로 쓴다 |
| 초급 | 결과를 보고 다시 요청하지만 기준이 막연하다("더 좋게") |
| 중급 | 눈으로 확인할 수 있는 기준으로 다시 요청하고, AI가 범위를 넘으면 바로잡는다 |
| 고급 | 일을 시작하기 전에 범위 · "다 됐다"의 기준 · 검증 방법을 정해 맡기고, 결과를 스스로 검증한다 |

## 양식 (결과 파일에 그대로 쓴다)

```markdown
# AI 활용 현황 — <GitHub아이디>

- 관찰한 에이전트 · 기간: (도구 이름), 11/19 ~ 11/25
- 근거 자료: (대화 · PR #… · 이슈 #… · ai-cases 사례 번호)

**현황: (수준) — (한 줄 요약)**

| 이미 잘하는 것 | 근거 |
| --- | --- |
| | "(한 말이나 행동, 짧게)" |

**AI가 틀린 것을 잡은 순간** (1~2개)
- (무엇을 보고 알았나 → 어떻게 바로잡았나, 사례 링크)

**맡긴 일 / 직접 한 일**
- 맡긴 일:
- 직접 한 일(맡기지 않은 이유):

**다음 단계** (2~3개)
- (실제로 헷갈리거나 다시 한 장면에서, 다음에 이렇게 하면 된다는 한 줄)

**에이전트가 한마디** (선택, 1~2줄)
```

## 예시 (다른 프로젝트에서 쓴 것 — 형식 참고용)

> **현황: 실전에서 잘 쓰는 중급, 고급으로 넘어가는 단계**
>
> | 이미 잘하는 것 | 근거 |
> | --- | --- |
> | 결과를 보고 구체적으로 다시 요청 | "3배 빠르게", "나무 12그루"처럼 눈으로 확인할 수 있는 기준 |
> | AI가 선을 넘으면 바로 잡기 | "인터뷰만 하라고 했는데 코드를 만들었네" |
> | 기록과 과정 중시 | PRD · README · 결정 기록을 남기며 작업 |
>
