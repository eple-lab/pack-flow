# 리뷰 양식 — PackFlow 전체 (ART: Agent Review Template)

> 자기 구역이 아니라 **PackFlow 전체**를 한 사용자 · 검토자로 보고 쓴다. 11/25 작성.
> 결과 파일: `docs/records/review-<GitHub아이디>.md` (사람마다 한 파일)
> 참고: 팀원이 수업에서 쓴 ART(Agent Review Template)를 PackFlow에 맞게 바꿨다.

## 작성 방법

1. 시연 서비스(demo 배포 URL)를 **자기 시험 계정으로** 직접 써 보고, 저장소 문서를 근거로 아래 세 항목을 체크한다. 에이전트에게 맡겨도 되지만 화면 확인은 사람이 한다.
2. 각 항목은 `[x]`(확인함) · `[ ]`(확인 못 함)으로 표시하고, **근거를 한 줄 이상** 붙인다 — 테스트 ID(`T-…`), 회귀 결과표 줄, PR · 이슈 번호, 캡처 경로(`docs/records/img/`).
3. 문제를 찾으면 고치지 말고 GitHub 이슈(버그 양식)로 올리고 번호를 적는다.
4. 공개 저장소다 — 시연 계정 주소 · 비밀번호 · 키 · 실명 · PC 경로가 캡처와 글에 없게 한다.

## 양식 (결과 파일에 그대로 쓴다)

```markdown
# PackFlow 리뷰 — <GitHub아이디>

- 확인 일시 · 대상: 2026-11-25 HH:MM / demo 배포 (main 커밋 abc1234)

# ART (Agent Review Template)

[ ] **1. 원하는 기능이 의도한 대로 동작하나요?**
- 계획서 Step 1~5의 기능이 실제로 되는지 — 화면에서 직접 해 본 것과 결과
  | Step | 해 본 것 | 결과 | 근거(테스트 ID · 캡처) |
  |---|---|---|---|
  | 1 입고 · 출고 → 재고 · 대시보드 | | | |
  | 2 로그인 · 권한(남의 데이터 안 보임) | | | |
  | 3 취소 · 상태 전이 · 재고 초과 거부 · 일괄 등록 | | | |
  | 4 대량 데이터 · 회귀 결과 | | | |
  | 5 AI 발주서 초안 · 챗봇([확인] · [실행] 전에는 변화 없음) | | | |
- 근거: [제출용 테스트 결과서](../test-report.md), 회귀 결과표 `regression-*.md`

[ ] **2. 보안 검토를 수행했나요?**
- 키 · 비밀번호가 코드 · 문서 · 커밋에 없는지 (pre-commit 비밀값 검사, [05 보안](../../05-security.md))
- 사용자 입력 검증 — 빈 값 · 범위 밖 · 형식 오류가 화면과 서버에서 같은 문구로 거부되는지 (T-VAL)
- 권한 — 다른 계정의 데이터가 보이거나 바뀌지 않는지 (RLS, T-AUTH)
- AI — LLM 응답이 DB를 바로 바꾸지 않는지, "이전 지시를 무시하라" 같은 입력에 실행하지 않는지 (T-AI-4)
- 외부 코드 · 데이터 · 모델의 출처와 라이선스 ([LICENSES](../../LICENSES.md))

[ ] **3. 에러가 난 부분을 디버깅하여 "문제를 해결한 기록"을 남겼나요?**
- 에이전트가 만든 코드의 오류를 어떻게 발견하고 고쳤는지 — [13 고친 기록](../../13-fixes.md), AI 사례 `ai-cases-*.md`
- 새로운 시도 · 추가 실험이 기록되어 있는지 — 결정 기록 [02](../../02-decisions.md), [일자별 기록](../../daily/)
- 내가 본 기록 중 원인 · 수정 · 재확인이 가장 잘 남은 것 1개와 부족한 것 1개
```
